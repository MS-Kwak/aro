사업 및 개발 계획 제안서

# 아로 (ARO)

동네 단골 + 동네 모임 플랫폼

*사장님의 마음에, 손님의 마음에 아로새기다*

작성: 민서 (MSK)

공유 대상: 황형 ((주)보노보플랫폼)

2026년 7월

## 1. 한눈에 보는 요약

'아로(ARO)'는 동네 가게(카페 등)에 QR 스탬프 기반 단골 관리와 AI 재방문 마케팅을 제공하고(B2B 구독 수익), 소비자에게는 동네 소모임을 열고 참여하는 기능을 제공하는(참가비 수수료 수익) 하이퍼로컬 플랫폼입니다. 서비스명은 '아로새기다'에서 따왔습니다 — 손님이 스탬프를 새기고, 가게가 단골을 마음에 새기는 서비스의 본질을 담은 이름입니다. 두 축은 서로를 강화합니다. 가게가 늘면 모임 장소와 혜택이 늘고, 모임이 늘면 가게의 비수기 시간대 매출이 늘어 구독을 유지할 이유가 생깁니다.

핵심 전략은 오프라인 영업 없이 100% 온라인으로 고객을 획득하는 것입니다. 사장님이 광고를 보고 들어와 5분 안에 스스로 가입을 끝내는 셀프서브(Self-serve) 구조와, 지역이 아닌 업종(개인 카페) 중심의 버티컬 마케팅이 그 수단입니다.

아로는 AI 응대 자동화(기존 ARO 기획)와 단골·모임 플랫폼을 하나의 브랜드, 하나의 개발 로드맵으로 통합한 서비스입니다. AI 코어를 새로 개발하면서 단골·모임 기능을 같은 기반 위에 함께 구축하면, 단골 방문 데이터가 AI의 첫 실전 적용 사례가 되고 개발 리소스도 이원화되지 않습니다. 정부지원사업(혁신 소상공인 AI 활용지원)에 신청한 이름과의 연속성도 유지됩니다. mapstory에서 확보한 지도 기술(코드 자산)은 동네 가게·모임 탐색에 재활용합니다. 개발은 Next.js 중심으로 진행하고, 앱 스토어 배포 시 React Native로 래핑하는 방식으로 개발 부담을 최소화합니다.

## 2. 왜 이 사업인가

### 2-1. 시장의 빈자리

소상공인 단골 관리 시장은 도도포인트 서비스 종료 이후 사실상 비어 있습니다. 배민·네이버·카카오는 신규 고객 유입 채널이지 단골(재방문) 관리 도구가 아니며, 사장님들은 여전히 종이 쿠폰과 감에 의존합니다. 한편 1인 가구 증가로 '연애가 아닌 동네 친구·취미 모임' 수요는 꾸준히 커지고 있으나, 당근 모임·문토 등은 만남 자체에 집중할 뿐 동네 가게와 연결되어 있지 않습니다.

### 2-2. 우리가 가진 강점

- **ARO 통합 개발 —** LLM/RAG 기반 AI 응대 자동화(카카오톡·인스타 DM·네이버 톡톡) 설계가 이미 완료되어 있으며, 본 플랫폼과 병행 개발하여 유료 티어의 킬러 기능으로 탑재. 정부지원사업(혁신 소상공인 AI 활용) 스토리와도 직결

- **mapstory 기술 자산 —** mapstory 개발로 확보한 지도 기반 서비스 코드 자산을 동네 가게 지도, 모임 장소 탐색에 재활용 (mapstory 자체는 마케팅 전 단계로 이용자 확보 이전이나, 기술 검증은 완료)

- **팀 —** 프론트엔드·백엔드 개발(민서) + DB 설계·기획(황형/보노보플랫폼)의 검증된 장기 협업 체제. 아이디어와 핵심 의사결정은 공동 협의

- **기술 —** Next.js + Supabase 중심 개발, 앱은 React Native 래핑으로 스토어 배포 — 웹/앱 코드베이스를 하나로 유지해 개발 리스크 최소화

### 2-3. 두 축이 만드는 선순환

① 카페 사장님이 온라인 광고를 보고 셀프 가입 → QR 스탬프를 카운터에 부착 → ② 손님이 적립하며 소비자 유저로 유입 → ③ 사장님이 '화요일 저녁, 우리 가게를 모임 장소로 개방' 등록 → ④ 모임 호스트가 장소를 검색해 모임 개설 → ⑤ 모임 참가자들이 해당 가게의 단골이 됨 → 다시 ①의 가치가 커짐. 양쪽 모두 온라인으로 유입되지만, 실제 만남과 소비는 오프라인 동네에서 일어나는 구조입니다.

### 3-2. 왜 무료부터 시작하는가

무료 스탬프는 미끼가 아니라 데이터 축적 장치입니다. 사장님이 무료로 쓰는 동안 단골 방문 데이터가 쌓이고, '3주째 방문이 없는 단골 12명에게 쿠폰을 보내볼까요?'라는 제안이 가능해지는 순간이 유료 전환 시점입니다. 즉 제품 스스로가 영업사원 역할을 하는 PLG(Product-Led Growth) 구조입니다.

## 4. 온라인 고객 획득 전략 (GTM)

오프라인 영업을 배제하는 대신, 다음 두 가지 원칙으로 전략을 재설계했습니다.

### 4-1. 원칙 ① 제품이 영업사원: 셀프서브 온보딩

사장님이 광고 클릭 후 아무와도 통화하지 않고 가입을 끝낼 수 있어야 합니다. 목표는 '가입 → 가게 정보 입력 → QR 스탬프 PDF 다운로드 → 카운터 부착'까지 5분. 온보딩 중 이탈하는 구간을 데이터로 추적해 지속 개선합니다.

### 4-2. 원칙 ② 지역이 아닌 업종으로 공략: 버티컬 마케팅

온라인에서 '특정 동네 사장님' 타기팅은 비효율적이지만 '카페 사장님' 타기팅은 효율적입니다. 개인 카페 사장님은 인스타그램에서 서로 팔로우하는 촘촘한 네트워크를 형성하고 있어, 한 업종 안에서 성공 사례가 나오면 옆 가게로 자연 확산됩니다. 1차 버티컬은 개인 카페(단골 개념이 가장 강하고 사장님의 디지털 친화도가 가장 높음), 이후 네일·미용실·필라테스로 확장합니다.

### 4-3. 채널별 실행 계획

| **채널**              | **실행 내용**                                                                                                                                    | **담당(안)**      |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|-------------------|
| 자영업 커뮤니티       | 네이버 카페 '아프니까 사장이다'(회원 약 100만) 등에 후기·정보성 콘텐츠, 체험 사례 공유                                                           | 공동 (기획: 황형) |
| 인스타그램 릴스       | '단골 관리 전후' 비포애프터, 사장님 인터뷰 숏폼 콘텐츠                                                                                           | 공동 + 초기 고객  |
| 블로그 SEO / 검색광고 | '카페 단골 관리', '스탬프 앱', '재방문 마케팅' 키워드 공략                                                                                       | 공동              |
| 모임 호스트 모집      | 러닝크루장·독서모임 리더·원데이클래스 강사 등 팔로워 보유자를 호스트로 영입. 정산·출석·홍보 도구 무료 제공, 호스트가 참가자를 직접 데려오는 구조 | 공동 (기획: 황형) |

소비자(모임 참가자)를 광고로 직접 모집하는 것은 비용 대비 효율이 낮아 지양합니다. 호스트가 자신의 팔로워를 데려오게 하는 것이 문토·프립이 검증한 성장 공식입니다.

### 4-4. 지역 밀도는 사후적으로 발견

셀프 가입 가게가 자연스럽게 뭉치는 지역(수도권 예상)을 데이터로 발견한 뒤, 해당 지역에 광고비를 집중 투입해 밀도를 완성합니다. 밀도를 미리 만드는 것이 아니라, 생기는 곳을 찾아 증폭하는 접근입니다.

## 5. 수익 시뮬레이션

### 5-1. 핵심 가정

| **항목**                 | **가정치**     | **비고**                         |
|--------------------------|----------------|----------------------------------|
| 유료 구독료              | 월 4만원       | 배민 광고비 대비 저가            |
| 무료 → 유료 전환율       | 35%            | SaaS 통상 20~40%                 |
| 모임 평균 인원 / 참가비  | 6명 / 15,000원 | 소셜다이닝·클래스 시세 하단      |
| 플랫폼 수수료율          | 12%            | 프립(10~20%)의 중간값            |
| 유료 고객 획득 비용(CAC) | 10~20만원      | 온라인 광고 기준 추정            |
| 유료 고객 연간 가치(LTV) | 48만원+        | 월 4만원 × 12개월 이상 유지 가정 |

CAC 10~20만원 대비 LTV 48만원 이상이면 광고비 회수가 계산되는 구조입니다. 다만 이는 활성화율(아래 7장)이 유지될 때만 성립합니다.

### 5-2. 24개월 시나리오

| **시나리오** | **12개월 차**  | **24개월 차**  | **전제**                       |
|--------------|----------------|----------------|--------------------------------|
| 보수         | 월 120만원     | 월 330만원     | 본업 병행, 완만한 성장         |
| **기본**     | **월 280만원** | **월 670만원** | **12개월 차부터 마케팅 강화**  |
| 낙관         | 월 550만원     | 월 1,870만원   | 업종 내 바이럴 확산, 밀도 상승 |

### 5-3. 비용과 손익분기

고정비는 매우 가볍습니다. 인프라(Supabase + 서버)는 초기 월 10~30만원 수준이며, PG 수수료 약 3%는 모임 수수료 12% 안에서 흡수됩니다. 현금성 고정비 월 100만원 미만으로 시작 가능하며, 유료 가게 약 25곳 수준에서 운영비 손익분기를 넘습니다. 마케팅 비용을 포함한 실질 손익분기는 기본 시나리오 기준 15~18개월 차로 추정합니다.

단, 24개월 차 월 670만원(기본)은 두 사람의 본업을 대체하는 규모는 아니며, '탄탄한 부수입 + 성장하는 자산' 단계입니다. 이런 로컬 SaaS는 유료 가게 수백 곳 규모에 도달하면 인수 대상이 되거나 정부지원사업·투자 유치의 스토리가 명확해지는 장점이 있습니다.

## 6. 개발 계획

### 6-1. 기술 스택

| **레이어**           | **기술**                              | **선정 이유**                                                      |
|----------------------|---------------------------------------|--------------------------------------------------------------------|
| 웹 (사장님 + 소비자) | Next.js + TypeScript                  | 대시보드와 소비자 웹앱을 단일 코드베이스로, 셀프 온보딩·SEO에 유리 |
| 모바일 앱            | React Native (웹뷰 래핑)              | Next.js 웹앱을 앱 셸로 감싸 스토어 배포, 별도 앱 개발 비용 최소화  |
| 백엔드 / DB          | Supabase (PostgreSQL, Auth, Realtime) | 빠른 MVP, RLS 보안, pgvector로 AI 확장 (DB 설계: 황형)             |
| AI 자동화            | ARO 모듈 신규 개발 (GPT-4.1 Mini)     | 본 플랫폼과 병행 개발, 카톡·인스타·톡톡 채널 연동                  |
| 결제                 | 토스페이먼츠 등 PG 연동               | 모임 참가비 결제·정산                                              |
| 인프라               | Linux + PM2 + Nginx                   | 기존 운영 경험 재활용                                              |

### 6-2. 단계별 개발 범위

| **단계**                | **범위**                                                                                                                            | **검증 목표**                             |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------|
| **1단계 MVP (2~3개월)** | 사장님 셀프 온보딩(웹), QR 스탬프 적립·쿠폰, 단골 대시보드, 소비자용 적립 웹앱(설치 없는 웹 우선)                                   | 활성화율: 가입 사장님의 QR 실제 부착 비율 |
| 2단계 (+2~3개월)        | ARO 코어 개발(AI 응대·이탈 단골 감지 → 자동 쿠폰 발송)을 본 플랫폼에 첫 적용, 유료 결제, RN 웹뷰 래핑으로 스토어 출시               | 무료 → 유료 전환율 (목표 35%)             |
| 3단계 (+3개월)          | 모임 기능: 호스트 개설·참가비 결제·출석 관리, 가게의 모임 장소 등록, 지도 탐색(mapstory 코드 재활용). ARO 채널 확장(인스타 DM·톡톡) | 호스트당 월 모임 수, 모임 → 단골 전환     |

1단계 MVP를 의도적으로 작게 잡았습니다. 스탬프·쿠폰·대시보드만으로 '사장님이 스스로 가입하고 실제로 쓰는가'를 검증한 뒤에 유료 기능과 모임을 얹는 순서입니다. 소비자 쪽은 초기에 앱 설치 장벽을 없애기 위해 QR 스캔 즉시 열리는 웹앱으로 시작하고, 2단계에서 동일 웹앱을 React Native로 래핑해 스토어에 출시합니다.

ARO를 별도 제품으로 먼저 완성한 뒤 연동하는 것이 아니라, 2단계부터 본 플랫폼 안에서 ARO 코어를 개발·적용합니다. 이렇게 하면 ARO가 처음부터 실제 가게 데이터 위에서 검증되고, 하나의 Supabase 기반 위에서 두 서비스가 자라므로 개발 리소스가 분산되지 않습니다. 향후 ARO를 독립 서비스로 분리할 때도 이 플랫폼의 가게들이 첫 레퍼런스 고객이 됩니다.

### 6-3. 개발 일정 (안)

민서의 LG CNS GCAS 프로젝트가 9월 UAT 후 종료되는 일정을 고려하여, 7~9월은 설계·프로토타입 병행 개발, 10월부터 풀타임 투입해 연내 1단계 MVP 출시, 2027년 상반기 내 3단계까지 완료를 목표로 합니다.
