# 아로(ARO) 화면정의서 리뷰

## 서비스 개요

소상공인(사장님)용 **QR 스탬프 적립 + AI 리뷰 응대 + 이탈 단골 마케팅** 솔루션

## 전체 구조 - 잘된 점

- **사장님 / 손님** 화면이 명확히 분리되어 있음
- **무료 → 유료** 전환 경계가 깔끔 (Screen 12부터 유료)
- **온보딩 3단계**(가게정보 → 리뷰연동 → QR생성)가 논리적이고 진행률 시각화로 완주율 높일 수 있음
- 손님 쪽은 앱 설치 불필요(QR 스캔 → 브라우저)로 진입 장벽 최소화

## 화면별 상세 피드백

### SCREEN 03 - 회원가입·로그인

- 카카오 CTA가 메인인 건 좋음 (소상공인 친숙도 높음)
- **개선:** Apple 로그인도 보조로 넣는 것 권장 (iOS 앱스토어 정책상 소셜 로그인 제공 시 Apple 필수)
- **개선:** "비밀번호 찾기"가 이메일 인증 방식이라 되어 있는데, 구체적 플로우(이메일 발송 → 재설정 링크) 화면 필요

### SCREEN 04 - 가게 정보 입력

- 잘된 점: 필수/선택 구분 명확
- **개선:** 업종 선택지 명시 필요 (카페, 네일, 미용, 음식점, 편의점 등). 업종에 따라 리워드 추천이 달라질 수 있음
- **개선:** 영업시간 "요일별" UI가 복잡할 수 있음 → "평일/주말" 기본 + "요일별 상세" 토글 추천

### SCREEN 05 - 리뷰 플랫폼 연동

- **개선:** "건너뛰기" 옵션 중요 → 리뷰 플랫폼 없는 사장님도 QR 스탬프만 사용 가능하게
- **개선:** URL 입력 시 유효성 검증 피드백 필요 (올바른 네이버 플레이스 URL인지)
- 2단계(배민/쿠팡이츠)는 MVP에서 제외하고 "준비 중" 표시가 나을 수 있음

### SCREEN 06 - QR 생성·다운로드

- 잘된 점: A4 PDF 다운로드로 즉시 출력 가능
- **개선:** QR 디자인 커스터마이징 — 가게 로고 삽입 옵션이 있으면 차별화
- **개선:** QR 재발급 시 기존 QR 무효화 → 확인 모달 필수 (실수 방지)
- **고려:** QR 크기별 다운로드 (A4 전체 / 명함 크기 / 테이블텐트용)

### SCREEN 07 - 홈 대시보드

- 잘된 점: 4개 핵심 지표 + 빠른 액션 + 주간 차트
- **개선:** 주간 차트에 비교 데이터 (전주 대비 +12% 등) 추가하면 더 유용
- **개선:** "빠른 액션"이 3개인데, 가장 긴급한 것 1개를 강조 (예: 미답변 리뷰 빨간 뱃지)

### SCREEN 08 - 단골 목록

- 잘된 점: 탭 필터(전체/단골/이탈위험/신규) 구성
- **개선:** 검색 기능 필요 (전화번호 뒷자리로 검색)
- **개선:** "이탈위험" 기준이 뭔지 사장님이 이해할 수 있는 설명 툴팁 필요 (예: "21일 이상 미방문")
- **개선:** 전화번호 마스킹 처리(\*\*\*\*) 좋음, 하지만 "전체 보기" 옵션은 있어야 할 수도

### SCREEN 09 - QR 관리·쿠폰 설정

- 잘된 점: 스탬프 기준/리워드 내용/유효기간 필수·선택 구분
- **개선:** 리워드 예시 제안 기능 — 업종별 인기 리워드 추천 (예: 카페→"아메리카노 1잔", 네일→"기본 케어 50% 할인")
- "복수 리워드(5회·10회 각각)" 예정 표시 좋음, MVP에서는 단일 리워드로 시작

### SCREEN 10 - 리뷰 목록

- 잘된 점: AI 분류 + 미답변 우선 + 플랫폼 표시(네이버/카카오맵)
- **개선:** 별점 필터 추가 (1~2점만 보기)
- **개선:** 리뷰 카드에 작성 일자 표시 필요 (현재 보이지 않음)
- **개선:** "승인" 버튼 위치 — 리뷰 목록에서 바로 승인하면 편하지만, 실수 방지를 위해 상세 화면 거쳐서 승인이 더 안전 (현재 설계가 이렇게 되어 있어 좋음)

### SCREEN 11 - AI 답변 상세·승인

- 잘된 점: 원본 리뷰 + AI 초안 나란히, 인라인 편집, 다시 생성
- **개선:** "다시 생성" 월 10회 제한 → 남은 횟수 표시 필요
- **개선:** AI 톤 선택 (친근/정중/격식) 옵션이 있으면 좋음
- **개선:** "플랫폼에 등록" 클릭 후 결과 확인 (성공/실패) 피드백

### SCREEN 12 - 이탈 단골 마케팅 (유료)

- 잘된 점: 자동 발송 설정이 직관적
- **개선:** 발송 미리보기 — 실제 알림톡이 어떻게 보이는지 프리뷰
- **개선:** "발송 완료/대기" 상태 외에 "발송 실패" 케이스 처리 필요
- **개선:** 이탈 기준 "마지막 방문 후 N일"을 사장님이 커스텀할 수 있게 (현재 21일 고정?)

### SCREEN 13 - 발송 결과 리포트 (유료)

- 잘된 점: 4대 지표(발송 건수/쿠폰 오픈율/재방문 수/재방문율) + 주간 추이
- **개선:** ROI 계산 — "쿠폰 비용 vs 재방문 매출 추정" 같은 인사이트
- **개선:** 발송 이력에서 개별 고객 재방문 여부 클릭해서 확인

### SCREEN 14 - 카카오 채널 AI 챗봇 (서브옵션)

- **개선:** 이 기능은 복잡도가 높음 → MVP에서 제외하고 2단계로 미루는 것 권장
- 가게 정보 학습/FAQ/응대 톤은 온보딩이 필요 → 별도 설정 플로우

### SCREEN 15 - 구독·결제

- 잘된 점: 무료/프리미엄 2단계로 단순
- **개선:** "7일 무료 체험" 추가 → 유료 전환율 크게 상승
- **개선:** 구독 취소 시 "당월 말까지 유지" 명시
- **개선:** 프리미엄 기능별 잠금 아이콘을 무료 화면에서 보여주면 업셀 유도 효과적

### SCREEN 16~19 - 손님 플로우

- 잘된 점: 앱 설치 없이 브라우저로 완결, 최소 입력
- **개선 (Screen 17):** 전화번호 입력 시 개인정보 동의 체크박스 법적 필수
- **개선 (Screen 18):** 카카오톡 공유 시 가게 이름 + 스탬프 수 — 바이럴 효과 좋음
- **개선 (Screen 19):** 쿠폰 1회 사용 후 무효화 → 사용 완료 상태 UI 필요
- **고려:** 손님이 자기 적립 현황 조회 할 수 있는 링크 (전화번호 입력 → 스탬프 현황)

## 설계 결정사항 (2026-07-21 확정)

### 1. 손님 재방문 인식 방식

**방식: localStorage + 전화번호 앞 3자리 조합**

- 첫 방문: 전화번호 전체 입력 + SMS 인증 (4자리 코드)
- 2회차 이후: localStorage에 저장된 전화번호 앞 3자리를 자동 채움 → 손님이 나머지만 입력
- localStorage 삭제 시 (다른 브라우저, 시크릿 모드): 전화번호 전체 재입력 (SMS 재인증 없이 기존 번호면 바로 적립)
- 쿠키 대신 localStorage 선택 이유: 서버 전송 없어 보안 부담 적음, 용량 넉넉(5MB), 동일 도메인 유지

### 2. 개인정보 동의 (Screen 17 보완)

**Screen 17 전화번호 입력 폼 하단에 필수 체크박스 추가**

```
□ [필수] 개인정보 수집·이용에 동의합니다 (보기)
```

- "보기" 클릭 시 바텀시트로 표시: 수집항목(전화번호), 목적(스탬프 적립·쿠폰 발송), 보유기간(서비스 이용 종료 시 파기)
- 체크 안 하면 "적립하기" 버튼 비활성화
- 동의 이력은 Supabase `consents` 테이블에 저장 (customer_id, agreed_at, version)

### 3. 스플래시/랜딩 페이지 (Screen 01-02 추가)

| 화면                        | 내용                                                                                            | 구현 시점        |
| --------------------------- | ----------------------------------------------------------------------------------------------- | ---------------- |
| **Screen 01 (사장님 랜딩)** | 마케팅 유입 페이지. 태그라인 + 핵심 가치 3줄 + "무료로 시작하기" CTA + 하단 스크롤 시 기능 소개 | 1단계 MVP        |
| **Screen 02 (스플래시)**    | 앱 진입 시 아로 로고 + 태그라인 1초 표시 후 자동 전환. 웹은 불필요, RN 앱 래핑 시에만 사용      | 2단계 앱 출시 시 |

### 4. 빈 상태(Empty State) UI

각 화면별 맞춤 빈 상태 일러스트(아로 심볼 연회색) + 행동 유도 문구 + CTA 버튼 적용
